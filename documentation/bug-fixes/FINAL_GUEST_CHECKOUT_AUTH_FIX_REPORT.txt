FINAL_GUEST_CHECKOUT_AUTH_FIX_REPORT

A. Root Cause
The HTTP 403 Forbidden error during Guest Checkout was caused by a silent schema stripping issue. When a guest checkout is initiated, the backend successfully generates a plaintext \guestToken\, hashes it using \crypt\, and calculates an expiry time. These are passed to \Order.create()\. However, because the fields \guestId\, \guestTokenHash\, and \guestTokenExpires\ were **missing from the Mongoose \Order\ schema**, Mongoose's default \strict: true\ behavior silently dropped them during the database insert. Consequently, when the frontend requested the order details using the query parameter \?guestToken=...\, the backend could not find \order.guestTokenHash\ in the database document. Because it was \undefined\, the bcrypt comparison block was skipped, falling through to the default 403 Access Denied fallback block.

B. Guest Token Lifecycle
1. FE guest checkout sends \isGuest: true\.
2. BE POST \/api/orders\ generates a 32-byte hex token, hashes it with \crypt\, and calculates a 3-hour expiry.
3. BE saves the order with \guestTokenHash\ and \guestTokenExpires\ (which previously failed due to schema strictness).
4. BE returns the plaintext \guestToken\ to the FE.
5. FE saves the token in \localStorage\ via \saveGuestOrderToken()\.
6. FE redirects to \/payment/:orderId\.
7. FE loads the token from \localStorage\ and appends it to \GET /api/orders/:id?guestToken=...\.
8. BE compares the plaintext token against the stored \guestTokenHash\ using \crypt.compare\.

C. Order Creation Flow
Remains completely intact. Guest token generation and hashing are cryptographically sound. The missing piece was simply schema definition.

The implementation securely passes a cryptographically random plaintext token back to the client while storing only a salted bcrypt hash in the database. This guarantees that even if the database is exposed, the guest tokens cannot be reverse-engineered. The guest endpoints are strongly isolated from authenticated user endpoints. Arbitrary ownership impersonation is prevented.
