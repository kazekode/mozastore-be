F. Check-Payment Flow
- Frontend memanggil `/api/orders/:id/check-payment` yang akan memvalidasi payment.
- Sebelumnya gagal (return `paid_but_stock_failed`), namun sekarang sukses me-return `completed`.

G. Root Cause of Transaction userId Error
- Error `Transaction validation failed: userId: Path 'userId' is required.` terjadi di `processOrderPaymentSuccess` pada `Transaction.create()`.
- Hal ini karena schema `Transaction` mengharuskan `userId` yang bertipe numeric `Number` untuk setiap transaksi. Namun, guest checkout tidak memiliki `userId`.

H. Transaction Schema Analysis
- Diperlukan untuk statistik terpusat dan history webdash/tele.
- Schema mewajibkan `userId` dan disinkronisasikan antara BE, Tele, dan Webdash. 

I. Guest Transaction Design
- Desain yang diterapkan: Mengubah schema `Transaction` agar `userId` tidak lagi required (`required: false`).
- Menambahkan field `isGuest` (Boolean) dan `guestId` (String).
- Mengkondisikan payload di `processOrderPaymentSuccess`: Jika guest order, ia menyimpan `isGuest: true` dan `guestId`; jika bukan, ia menyimpan `userId`.

J. Stock Finalization
- Stock sekarang difinalisasi dengan benar menjadi 'sold'. Sebelumnya rollback (tetap 'reserved') karena MongoDB Transaction abort akibat error validasi schema `Transaction`.

K. Order Finalization
- Order sukses berubah status menjadi 'completed'.

L. Payment State
- Sistem tidak lagi gagal menyimpan hasil `paid` dari payment gateway. Payment state langsung ter-commit dan final.

M. Idempotency
- Menggunakan `$set` dan `session`. Karena `processOrderPaymentSuccess` di dalam check-payment memvalidasi `status: 'pending'`, percobaan polling dari frontend setelah sukses hanya me-return "Order already processed". Tidak ada duplicate transaction atau stats.

N. Authenticated User Regression
- User Auth (Telegram/Web) diuji ulang dan berjalan normal (menyimpan field numeric `userId` di `Transaction`). Stats `totalSpent`, `totalTransactions`, dll. berjalan normal.

O. Telegram Regression
- Kode dishare melalui `tele/lib/shared-db`. Bot telegram menggunakan schema dan service baru yang mana auth `userId` (Telegram numeric id) tidak terpengaruh.

P. Webdash Regression
- File diupdate di `webdash/lib/shared-db` juga, kompatibilitas terjamin.

Q. Statistics Regression
- `$inc` di `User.updateOne` dilindungi dari guest (`if (!order.isGuest && order.userId != null)`). Hal ini mencegah mongoose mengubah acak User stats karena filter `{ userId: undefined }`. 
- `statistics.js` mengandalkan `Order` collection, bukan `Transaction`. Guest stats (source: 'web') tetap terhitung sempurna.

R. Security Check

S. Database Safety
